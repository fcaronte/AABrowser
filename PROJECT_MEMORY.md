    - Metadata updates no longer force STATE_PLAYING (a paused page stays paused on AA).
  - **Self-pause right after a playback starts (page change) fixed**: `CarMediaService` called `requestAudioFocus()` on every metadata update (and on AA play). The WebView (Chromium `AudioFocusDelegate`) already holds audio focus while playing, so the service stole it and Chromium paused the video ~1 s after it started (seen in logcat: WebView requestAudioFocus -> service requestAudioFocus -> `onAudioFocusChange(-1)` to `AudioFocusDelegate` -> page `pause`). Same fix as commit `bd244ca` ("fix spotify auto pause"), which had been undone by `3053222`.
  - **YouTube tap-to-seek (Main + Wide)**: the m.youtube.com player (2026: `div.ytPlayerProgressBarDragContainer[role=slider]`, 44 px tall) seeks only by dragging; a tap on the bar is ignored (reproduced with Chrome 155 headless, same UA/viewport as the car WebView: 1075x514 CSS px, dpr 0.744). New `YouTubeManager.getTapToSeekScript()`, injected by `WebViewScriptRouter` for YouTube: a still tap inside the visible bar seeks to that point (skips overlapping buttons, ads, live streams). Drags are untouched (no preventDefault/stopPropagation). In the Wide dragging is still impossible: the Car App Library `onScroll` gives only distances, no finger position, and is converted to page scroll.
  - **YouTube voice search (Wide)**: m.youtube.com voice search does not use `SpeechRecognition`; it records with `getUserMedia({audio})` (checked in the ytmweb bundle). The Wide `onPermissionRequest` granted only `RESOURCE_PROTECTED_MEDIA_ID`, so the mic was denied (`NotAllowedError`). Now it also grants `RESOURCE_AUDIO_CAPTURE` (camera still denied); the Main already granted it.
  - **Wide keyboard re-enabled (⌨️ in the input popup)**: the old flow injected the text into `document.activeElement` after the full-screen `SearchTemplate` closed, but meanwhile the page loses focus (`activeElement` = BODY), so the text went nowhere. Now `openFieldInput()` first runs `BrowserJavascript.getCaptureInputTargetScript()` (stores the field in `window.__aabTypingTarget`, returns value/hint; password values never returned), opens `WideSearchScreen` prefilled (`initialText`, `allowEmpty`), then `getSetInputTextScript(text)` re-focuses that field, sets the value with the native setter (React-safe) + `input`/`change`, and submits only search fields (`form.requestSubmit()` or Enter). Tested in local Chrome 155 (WebView UA): YouTube search after blur -> `/results?search_query=...`; login field typed, not submitted. The popup is suppressed for 1.5 s after typing (`INPUT_POPUP_SUPPRESS_MS`). A docked "bottom" keyboard like the Main's is not available to Car App Library apps (only full-screen `SearchTemplate`/`SignInTemplate`); the Main uses the projected SDK `InputManager`, which template apps cannot use.
  - **Wide double-tap-zoom block on YouTube**: `getDisableDoubleTapScript()` used `style.innerHTML`, blocked by YouTube's Trusted Types ("This document requires 'TrustedHTML' assignment" in logcat), so the style never applied there. Now uses `style.textContent`.

## 3. Architectural Decisions
- **Explicit next/previous are not the buttons**: with seek declared and skip not, `onSkipToNext`/`onSkipToPrevious` come only from explicit requests (voice, assistant), so the scripts may do the real "next" there (YouTube: the suggested video). A page that wants its own next without turning Android Auto's −10/+10 s into skip buttons defines `window.aabNextItem`/`aabPreviousItem` (Podcast); registering `nexttrack` would change the buttons.
- **Favorites cross the lists**: TV favorites carry their list (`s`) and play from it, Radio favorites keep their data in `state.extra`, followed podcasts are global. A favorite never forces a change of the list chosen in the menu.
- **Prompts on the car screen are cards or overlays, never dialog windows** (page dialogs, certificates, site permissions, the Passenger disclaimer).
- **Podcasts: nothing but names and feed addresses from the catalog, no API keys** (Podcast Index and the like are not needed: Apple plus RSS/OPML cover everything; never put a key in the repository). Feeds are read with SAX so they can be tested on the JVM; anything that must stop early throws through `StoppingHandler.stop`.
- **Media keys the state does not declare never reach `onSkipToNext`**: Android Auto forwards them and the session gets them, but the framework default drops them. What must react to a key goes in `onMediaButtonEvent`. Declaring skip replaces Android Auto's on-screen ±10 s with skip buttons: only the user's choice `youtubeVideoSkip` does it on a single video.
- **Shares follow their own rule, not the voice one**: the Main by default, the Wide only when it is in front (`VoiceCommandRouter.shareTarget`). Voice commands keep `choose()`.
- **Podcasts (if built): nothing copyrighted in the repository**: no catalog, audio or covers shipped; charts and search asked at run time, audio from the publisher's server, covers from the feed, no Podcast Index key in the repository.
- **Share to CarWeb**: connected to the car it always goes to the car, also with "always"; only away from the car it opens the phone Main. The default stays "only with the car connected".
- **A file received from another app is read only through its grant**: the grant given with the intent dies with the receiving activity, so anything used later needs `grantUriPermission` on our own package (released at the next file). Never accept `file:` addresses or the app's own provider in an exported activity.
- **`onPageFinished` does not mean "this page is open"**: the WebView calls it also for cancelled navigations, with their address. Whatever stores the URL checks `view.url == url`, and a URL reported by the WebView never becomes a `loadUrl` (it would undo a Back and cut the forward pages).
- **Lists of TV and Radio are added only in the native Settings of the phone**: addresses and passwords never go through the page, which only asks to open Settings (bridge true only for the phone Main on `player.local`) or says to use the phone.
- **Phone Back**: every full-screen overlay has its `PhoneBackHandler` (later composed = answers first); the last Back on the home is the system's (handler off for 3 s), never a process kill, because the process also runs the car apps.
- **AdBlock list = downloaded, never bundled**: the lists (HaGeZi by default, AdGuard, or any address) are GPL-3.0 and change daily; the app downloads the chosen one (3 days), keeps only hashes outside the backup, and never replaces a good list with a broken download. Rules beyond plain domains (wildcards, regex, element hiding) are skipped on purpose: a full uBlock-style engine is step 3, only if needed.
- **Ads that catch taps**: without multiple windows a `_blank` link in a frame replaces the whole page, and `shouldOverrideUrlLoading` does not see frame navigations, so what happens inside a frame is decided by the page script (`POPUP_INTERCEPTOR_JS`). Blocking an ad is not enough when its transparent link stays over the player: remove the link and pass the tap to what is below. A blocked page answers 204, never an empty 200.
- **Pages opened by scripts**: every `window.open` and script-driven link goes through `PopupGuard` (same site, tapped link's site, sign-in; never an ad host); blocked windows get a fake window object, never null. New bridge methods that open pages must take the tapped link and ask `PopupGuard`; the per-site shield turns all of it off.
- **Commands from outside a screen go to the car first**: `VoiceCommandRouter` keeps every registration with `inCar`; the phone Main gets a command only when no car screen of that kind is open, and links shared to the car (`carOnly`) never go to the phone.
- **Only two car apps, CarWeb (projection) and CarWebWide (navigation)**: the Wide as a POI or weather category app (map template with the mandatory panel) was tried and dropped (user, 07/11/2026), and a third icon is not wanted. Do not retry other Car App Library categories for the Wide without new facts. Both apps must stay visible in Android Auto's menu: a hidden CarWebWide cannot be started from CarWeb (user test 07/11/2026), so a single icon is not possible.
- **Regular expressions run on ICU on Android**: `java.util.regex` there is ICU, stricter than the JVM of the unit tests (a lone `}` or `{` is a syntax error on the phone only, and a pattern in an `object` breaks the whole class). Always escape `{` `}` `[` `]` outside character classes and quantifiers; a new pattern can be checked against the system ICU on the PC (`uregex_open`).
- **Requests to the CarWeb Media pages stay in the app**: a voice request goes through `MediaVoice` and the page fetches it with its token; never through URL parameters (any site could navigate to them and a reload would repeat them). Native code never passes stream addresses or results through the plan.
- **One name matcher**: anything that finds a channel, station or file by name goes through `MediaMatcher`; start by itself only at `CONFIDENT` or above, otherwise show the list.
- **Gemini does not drive CarWeb**: in the car Gemini neither calls `onPlayFromSearch` nor sends a media search to Android Auto for CarWeb, even when CarWeb is an Android Auto media app (07/11/2026). Do not add components or categories to try again without new facts (a Google change, or a log line with `onPlayFromSearch from=` and Gemini's package). What Gemini does is open the package (`ACTION_MAIN`), and Android Auto gives it the Wide: `MainHandOver` brings the Main in front when "Il tocco sul player apre CarWeb" says so. Never close the Wide for it: Android Auto reopens it and sends the Main back.
- **The player card tap**: Android Auto sends it to the component in the session extra `android.media.session.BROWSE_SERVICE`, if it is in its menu; otherwise to the first app of the package in the menu (the Wide, which takes the navigation space and is reopened if it closes). Whatever component is declared there must also answer as a MediaBrowser (AA connects to it, and the card stays empty if nobody answers): `CarService` forwards to `CarMediaService`. Never add a MEDIA category car app for this: it is one more icon in the menu (user: only CarWeb and CarWebWide), and it becomes AA's media app for the package.
- **Station text is never a title as it is**: everything goes through `AABTrackParser`, and a lyrics result is accepted only when it matches artist and title (in either order); better no lyrics than another song's. Words like "now", "next", "dopo" count as labels only with a colon. Add new real samples to `track-parser.test.js`.
- **Fullscreen from code needs a user activation**: `requestFullscreen()` run by `evaluateJavascript` always fails. To enter fullscreen without the user, arm a layer in the page and dispatch a `MotionEvent` tap to the WebView (trusted input for Chromium), calling `requestFullscreen` inside the layer's `touchend` with `preventDefault`; never tap the page directly (it would pause the video or follow a link). Synthetic taps must not count as user taps (`lastTouchAt`). Never act on a WebView right after resume: wait for the window focus and a drawn frame (`postVisualStateCallback`), and never leave a layer in the page that depends on the page's timers to go away.
- **Car screens work only when parked unless Passenger mode is on**: "moving" is what Android Auto says (`DrivingState`, AA SDK `DRIVING_STATUS`), never our own checks (GPS, speed: user decision); unknown status = no lock. New car-screen UI must stay under the cover while locked (Main: below zIndex 97; Wide: below `driveLockReference`), except the voice listening card and messages. Anything that types in the car goes through the Passenger keyboard when it is on (`AppSettings.passengerKeyboard`, Main only with `carInputManager != null`). The AA SDK connection lives on its own thread: never move it to the main thread (an SDK callback error would close the app in the car).
- **The weather exists only in the car**: `CarMediaService` is also bound on the phone (Main tabs, system media resumption), so anything shown on the player when nothing plays must check `isInCar()`. Outside the car the only notification is the one of a page that plays (or is paused) on the phone. To remove the notification use `removeNotification()` (`stopForeground(REMOVE)`), never `cancel()` alone; any start through `startForegroundService` must still reach `startForeground` (`onStartCommand`).
- **Wide drags have no position**: never try to pick the column being dragged (Car App Library gives only distances). On YouTube video pages the page is pinned and the columns scroll (user's choice, nothing below the video on the left); everywhere else page and columns scroll together so every part stays reachable.
- **Every metadata change of `CarMediaService` goes through `setSessionMetadata()`**: while a voice command listens the player shows "In ascolto…" and other metadata must wait.
- **Voice from outside a screen (assistant, steering wheel keys) goes through `VoiceCommandRouter`**, never through the AA player owner: the user may want to speak with nothing playing or with another tab playing.
- **Never unmute a YouTube video the app did not mute, except once at the start of a `/watch` video**: previews and user mutes must stay muted (a playing preview takes the AA player).
- **Steering wheel buttons**: apps never get the press duration of "back" (Car App Library and AA SDK alike) nor the voice button (assistant). Voice from the wheel = the assistant + `onPlayFromSearch`; a held media key is the only other possible hook, and only if the car sends it (check the `Media button` log first).
- **Media keys follow audio, not the Android Auto card**: the steering wheel keys reach `CarMediaService` only when AABrowser is the app that last played audio. Never try to grab them by playing silence (the car may switch its source away from the radio); anything shown on the weather card must work without the keys (▶ through the card's own controls reaches the session).
- **What must work with nothing playing goes on the player, not on the keys**: Android Auto sends the taps on the player buttons (transport controls and custom actions) to the session it shows, always; the wheel keys follow the last audio app. Never put custom actions on page states: Android Auto fills the free slots of a player without skip actions with its own ±10 s seek buttons, and a custom action takes their place.
- **The Main does nothing while it is behind**: `MainCarActivity` stops its lifecycle when another app is in front, so Compose state changes (tabs, URLs, screens) wait until it starts again. Anything triggered from outside (voice, assistant, player buttons) that needs the page must bring the screen to the front (`bringToFront`) or act on the WebView directly; player commands (JS on the owner WebView) work anyway.
- **Voice command phrases live in `VoiceCommands` (code, all languages together), not in strings.xml**: the recognizer language is the phone's, the UI language can be another one. Add a phrase to every language's list, with canonical names ("youtube", "amazon": other spellings go to `ALIASES`, whole words only), and add a test line in `VoiceCommandsTest` (`./gradlew --offline :browser:testDebugUnitTest`). User-visible messages stay in strings.xml (11 locales).
- **Settings singletons are initialized in `CarApplication.onCreate()`**: Android Auto can start the process for the Wide only (or the media service), without any Activity or `MainScreen`, so anything the Wide reads (settings `State`s, lists, whitelist) must be loaded at process start, never from a Main screen.
- **Writing into page fields (Main and Wide)**: `INSERT_TEXT_JS` first (`execCommand('insertText')` at the caret, then a synthetic paste), never `innerText`/`textContent` + fake events first (Lexical reverts them, Quill puts them at the start). Wide replacing text: set the DOM selection and dispatch `selectionchange` before `insertText`. Plain inputs fallback: native value setter + input/change. Both screens find the field again (`activeElement`, else the captured `__aabTypingTarget` or the last focused `__savedInputElement`) and give it the focus back; the caret moves to the end only if it left the field. Text handed to the Android Auto keyboard must be one line. Test new typing code in headless Chrome on playground.lexical.dev and a Quill page.
- **Messages of the Main in the car go through the Main's own card** (`feedbackMessage` via `onShowFeedback`), never a `Toast`: from `MainCarActivity` a Toast appears on the phone, not on the car screen. The Wide uses `CarToast`.
- **Location for websites**: every site asks (`SitePermissionPrompts`); the phone permission is asked only when a site needs it (precise; if the user picks approximate the site gets that), and on the phone the site's request waits for Android's answer. Do not retain geolocation grants in the WebView (`callback.invoke(origin, allowed, false)`). Location on the car screen counts as background: without "Allow all the time" a site is refused with a message (a location foreground service would be the other way). No Settings button for the phone permission (the user read it as "location for every site").
- **Adding a default favorite**: add it to `getDefaultFavorites()` with a new id, map that id to `DEFAULTS_VERSION + 1` in `DEFAULTS_ADDED_IN` and raise `DEFAULTS_VERSION`; existing users get it once at the end of their list. Never reuse an id, also of removed defaults ("9" = DAZN, removed in 2.5).
- **Releases for the updater**: every GitHub release must carry the APK as an asset whose name ends in `.apk` (CI); the tag is compared as a dotted number with the installed `versionName`.
- **The Wide never calls `navigationStarted()`**: it does not guide, and Android Auto allows a single active navigation, so the call ended Maps' navigation in progress. The surface does not need it. Android Auto opens the Wide on a player card tap anyway (package with media service + template app) and re-creates the session if the Wide finishes itself: do not try to close it on those intents.
- **User agent before the request**: the server picks desktop/mobile from the request headers, so the UA must be set before the navigation starts (`loadUrl` after setting it, or a reload from `shouldOverrideUrlLoading`); setting it in `onPageStarted` only affects the next request. Navigator spoofing must be a document start script, gated on the UA the page was requested with.
- **Wide layout = per host layout**: anything learned from the visible/stable areas (buttons band) belongs to that stable area (full screen, split with the player, split with the menu are different layouts). Unknown layout = no assumptions: the page must never end up under the host UI.
- **AAB Media audio graph**: `createMediaElementSource(#media)` only inside a user tap (silence otherwise) and it cannot be undone for the page; the crossfade's second player stays detached from the DOM so the AA integration only ever sees `#media`.
- **Streams returned by `shouldInterceptRequest` must start at byte 0**: the WebView applies the request's Range itself (skip + read to EOF) and uses `available()` as the total size (an int: ranges starting beyond 2 GB cannot be served). Bound the stream at the end of the range, never pre-skip, and let the WebView set `Content-Length`.
- **No Media Session API in the WebView**: anything that relies on `navigator.mediaSession` (metadata, `setActionHandler`) works only through the polyfill in `MEDIA_SESSION_TRACKS_JS`, which must run at document start (it is in `getLifecycleAndMetadataScript`). YouTube video hosts are excluded on purpose (playlist logic).
- **Invalid certificates: always ask, never proceed silently**: `handler.proceed()` only after an explicit user choice, remembered per host:port + certificate fingerprint (persisted; Settings > Clear data > "Accepted certificates" forgets them). Never accept all errors globally: it would make every site open to interception.
- **`AndroidBridge` is an attack surface**: every `@JavascriptInterface` method can be called by any page and any iframe loaded in the WebView. Methods that reach the network, open URLs or touch files must check the page (main-frame host tracked per WebView) and validate their arguments (`UrlUtils.isWebUrl` for URLs). Never add a generic "fetch for the page" method.
- **The DAZN code stays** (login proxy `proxyFetch`, DAZN-only CORS preflight, click interceptor, site search): without it DAZN does not work at all, not even its unprotected content (user decision, 26/10/2026). Only the default favorite and the README mentions were removed; do not offer to remove the code again.
- **Pages open tabs and popups only right after a tap** (10 s, checked by the app only: a page-side `navigator.userActivation` check broke Google sign-in popups, which open after an await): any new bridge method that opens or navigates must check the recent tap; page dialogs are never answered by the app.
- **Backup**: cookies/site storage (`app_webview/`) and accepted certificates never go to Google's backup or to a new phone; anything new that stores logins or tokens must be added to both backup rule files.
- **Updates**: KingInstaller installs without asking, so the app hands it only an APK it verified itself (package, signing certificates, newer version); never fall back to an unchecked file or URI.
- **Update APK access**: download into the app's own external folder, never the public Downloads: there the app cannot read or delete files it did not create (`Permission denied`, measured with `run-as`), and a leftover with the same name makes the new file take another one. Stage in the cache, then validate package, signing certificates, and version before FileProvider handoff. Open KingInstaller on `.MainActivity`: it shows the loaded file and the install choices (user confirmed); `.ApkHandler` skips them. Reasons of a refusal go to `Log`, also in release: an update failure on someone's phone cannot be diagnosed otherwise.
- **hls.js full build**: never the light one for IPTV or radio: a third of the channels keep the audio in a separate track. Anything played through `IptvProxy` keeps the channel's headers down to the segments.
- **One page per WebView, no hidden copies**: never mirror a page of one app in a hidden WebView of the other (sites with one session per browser, like WhatsApp Web, drop one of the two). A dead WebView (`onRenderProcessGone`) is never reused: remove, destroy, recreate.
- **Site permissions**: microphone, location and car files reach a page only through `SitePermissionPrompts` (or the user's auto switch); the camera is always denied; DRM (`RESOURCE_PROTECTED_MEDIA_ID`) stays automatic. App pages (AAB Media) never ask.
- **Page text into scripts only as JSON strings** (`JSONObject.quote`): never hand-escape quotes. Native code that needs to run a script in a page evaluates it directly; never add bridge methods that evaluate page-provided text in the main frame (every frame can call the bridge).
- **Navigation helpers act only for the main frame and only toward web addresses**: intent:// fallbacks must pass `UrlUtils.isWebUrl`; Wide internal `about:` commands only from the home page.
- **Never answer CORS preflights for the server**: a fake `OPTIONS` 200 with permissive headers lets any page send credentialed requests the browser would block. Only for DAZN (target or Origin host via `DaznProxy.isDaznHost`), and never with substring host checks.
- **Reading Widevine logs**: "Create MediaDrmBridge with level N" is the numeric SecurityLevel (1 = L3 SW_SECURE_CRYPTO, 5 = L1 HW_SECURE_ALL), and secure decoders end in `.secure`. On Android, SW_SECURE_DECODE and above require hardware secure codecs (L1). L3 licences may lack keys a service reserves for L1 (DAZN): a clear video playing while protected ones fail with "requested key has not been loaded" means missing keys, not the network. Fetch/XHR wrappers must never build `new Request(input)` before passing the original input on (it consumes the body).
- **Exported components accept intents from any app**: the update receiver must never trust the intent's URL or file (official release prefix + package check before KingInstaller, which installs without asking).
- **Wide host validator**: release builds accept only the library allowlist hosts; if a new Android Auto host version is refused (the Wide does not appear in the car), check the `CarServiceWide` validator first.
- **SDK 37 local network**: any new feature that talks to LAN devices (WebView pages, sockets, mDNS) depends on `ACCESS_LOCAL_NETWORK`; it can be granted only from the phone UI.
- **Local player queues are per kind**: audio and video never share a queue; the playing file's kind decides next/previous, the visible tab is only a view.
- **Local player = web page of the app, not native**: same page in Main and Wide, video needs the WebView anyway, AA integration comes for free from the injected scripts (media listeners, Media Session). Files are served by the app (no blob URLs): seeking works, nothing to re-select after a reload, works on the car without a picker.
- **Page buttons must not be named "Play"/"Pausa"/"Riproduci"...**: `PLAY_SCRIPT`/`PAUSE_SCRIPT` click buttons by those labels/classes after toggling the media themselves, so a toggle button with such a label would undo the AA command (the player page uses icon-only `#playToggle`).
- **Who decides the AA player buttons (skip vs ±10 s)**: the URL gives only the defaults at page start (`onPageStarted`); after that the page is the source of truth (Media Session `nexttrack`/`previoustrack`, YouTube playlist check). Never recompute from the URL later in the same page, and never in WebView factory callbacks with the composable `url` (it is the URL the tab was created with).
- **Below `MainScreen`, `LocalContext` is not the Activity**: use `LocalActivity.current` (re-provided by `MainScreen`), never `LocalContext.current as? Activity`, and `LocalActivityResultRegistryOwner.current` may be null (Android Auto `MainCarActivity`).
- **Web file chooser contract**: the `ValueCallback` must be completed exactly once. Either call it and return true, or return false without calling it (the WebView then cancels by itself); doing both crashes with "Duplicate showFileChooser result". Only SAF intents are used, so no storage permission is needed.
- **Per-WebView media clients + single arbiter**: `MediaFocusManager` is the only place that decides who owns the AA player; `MediaSessionManager` instances never talk to each other.
- **Who can take the player**: a client claims it only on a real start (JS `play` event / unmute, or a paused→playing transition) and only if it can take focus (visible Main tab or the Wide). Background tabs that start by themselves (autoplay) are paused.
- **Stale reports never claim**: periodic updates (`timeupdate`, Spotify polling) from a non-owner that was already playing are treated as late reports and paused (rate limited to 1/s).
- **Focus release**: on page start, tab close, Wide surface/WebView release. The owner sends STATE_NONE + empty metadata so `CarMediaService` goes back to weather/idle.
- **Injected JS must be Trusted Types safe**: YouTube enforces `require-trusted-types-for 'script'`, so never assign strings to `innerHTML`/`outerHTML`/`insertAdjacentHTML` in injected scripts (use `textContent` / DOM APIs).
- **Never request Android audio focus from the app side** (`CarMediaService` or elsewhere): each WebView requests it through Chromium when its media really starts; any other request from our package takes it away and Chromium pauses the page. The WebViews also pause each other natively through audio focus, which is consistent with "last started wins".
