## 3. Architectural Decisions
- **Websites get the position only with the precise permission**, which the app asks only for web maps (weather uses the approximate one); `webLocation` turns it off without revoking it. Do not retain geolocation grants in the WebView (`callback.invoke(origin, allowed, false)`). Location on the car screen counts as background: "Allow all the time" (or a location foreground service) is needed there.
- **Adding a default favorite**: add it to `getDefaultFavorites()` with a new id, map that id to `DEFAULTS_VERSION + 1` in `DEFAULTS_ADDED_IN` and raise `DEFAULTS_VERSION`; existing users get it once at the end of their list. Never reuse an id.
- **Releases for the updater**: every GitHub release must carry the APK as an asset whose name ends in `.apk` (CI); the tag is compared as a dotted number with the installed `versionName`.
- **The Wide never calls `navigationStarted()`**: it does not guide, and Android Auto allows a single active navigation, so the call ended Maps' navigation in progress. The surface does not need it. Android Auto opens the Wide on a player card tap anyway (package with media service + template app) and re-creates the session if the Wide finishes itself: do not try to close it on those intents.
- **User agent before the request**: the server picks desktop/mobile from the request headers, so the UA must be set before the navigation starts (`loadUrl` after setting it, or a reload from `shouldOverrideUrlLoading`); setting it in `onPageStarted` only affects the next request. Navigator spoofing must be a document start script, gated on the UA the page was requested with.
- **Wide layout = per host layout**: anything learned from the visible/stable areas (buttons band) belongs to that stable area (full screen, split with the player, split with the menu are different layouts). Unknown layout = no assumptions: the page must never end up under the host UI.
- **AAB Media audio graph**: `createMediaElementSource(#media)` only inside a user tap (silence otherwise) and it cannot be undone for the page; the crossfade's second player stays detached from the DOM so the AA integration only ever sees `#media`.
- **Streams returned by `shouldInterceptRequest` must start at byte 0**: the WebView applies the request's Range itself (skip + read to EOF) and uses `available()` as the total size (an int: ranges starting beyond 2 GB cannot be served). Bound the stream at the end of the range, never pre-skip, and let the WebView set `Content-Length`.
- **No Media Session API in the WebView**: anything that relies on `navigator.mediaSession` (metadata, `setActionHandler`) works only through the polyfill in `MEDIA_SESSION_TRACKS_JS`, which must run at document start (it is in `getLifecycleAndMetadataScript`). YouTube video hosts are excluded on purpose (playlist logic).
- **Invalid certificates: always ask, never proceed silently**: `handler.proceed()` only after an explicit user choice, remembered per host:port + certificate fingerprint (persisted; Settings > Clear data > "Accepted certificates" forgets them). Never accept all errors globally: it would make every site open to interception.
- **`AndroidBridge` is an attack surface**: every `@JavascriptInterface` method can be called by any page and any iframe loaded in the WebView. Methods that reach the network, open URLs or touch files must check the page (main-frame host tracked per WebView) and validate their arguments (`UrlUtils.isWebUrl` for URLs). Never add a generic "fetch for the page" method.
- **Exported components accept intents from any app**: the update receiver must never trust the intent's URL or file (official release prefix + package check before KingInstaller, which installs without asking).
- **Wide host validator**: release builds accept only the library allowlist hosts; if a new Android Auto host version is refused (the Wide does not appear in the car), check the `CarServiceWide` validator first.
- **SDK 37 local network**: any new feature that talks to LAN devices (WebView pages, sockets, mDNS) depends on `ACCESS_LOCAL_NETWORK`; it can be granted only from the phone UI.
- **Local player queues are per kind**: audio and video never share a queue; the playing file's kind decides next/previous, the visible tab is only a view.
- **Local player = web page of the app, not native**: same page in Main and Wide, video needs the WebView anyway, AA integration comes for free from the injected scripts (media listeners, Media Session). Files are served by the app (no blob URLs): seeking works, nothing to re-select after a reload, works on the car without a picker.
- **Page buttons must not be named "Play"/"Pausa"/"Riproduci"...**: `PLAY_SCRIPT`/`PAUSE_SCRIPT` click buttons by those labels/classes after toggling the media themselves, so a toggle button with such a label would undo the AA command (the player page uses icon-only `#playToggle`).
- **Who decides the AA player buttons (skip vs ±10 s)**: the URL gives only the defaults at page start (`onPageStarted`); after that the page is the source of truth (Media Session `nexttrack`/`previoustrack`, YouTube playlist check). Never recompute from the URL later in the same page, and never in WebView factory callbacks with the composable `url` (it is the URL the tab was created with).
- **Below `MainScreen`, `LocalContext` is not the Activity**: use `LocalActivity.current` (re-provided by `MainScreen`), never `LocalContext.current as? Activity`, and `LocalActivityResultRegistryOwner.current` may be null (Android Auto `MainCarActivity`).
- **Web file chooser contract**: the `ValueCallback` must be completed exactly once. Either call it and return true, or return false without calling it (the WebView then cancels by itself); doing both crashes with "Duplicate showFileChooser result". Only SAF intents are used, so no storage permission is needed.
- **Per-WebView media clients + single arbiter**: `MediaFocusManager` is the only place that decides who owns the AA player; `MediaSessionManager` instances never talk to each other.
- **Who can take the player**: a client claims it only on a real start (JS `play` event / unmute, or a paused→playing transition) and only if it can take focus (visible Main tab or the Wide). Background tabs that start by themselves (autoplay, wide mirror tab) are paused.
- **Stale reports never claim**: periodic updates (`timeupdate`, Spotify polling) from a non-owner that was already playing are treated as late reports and paused (rate limited to 1/s).
- **Focus release**: on page start, tab close, Wide surface/WebView release. The owner sends STATE_NONE + empty metadata so `CarMediaService` goes back to weather/idle.
- **Injected JS must be Trusted Types safe**: YouTube enforces `require-trusted-types-for 'script'`, so never assign strings to `innerHTML`/`outerHTML`/`insertAdjacentHTML` in injected scripts (use `textContent` / DOM APIs).
- **Never request Android audio focus from the app side** (`CarMediaService` or elsewhere): each WebView requests it through Chromium when its media really starts; any other request from our package takes it away and Chromium pauses the page. The WebViews also pause each other natively through audio focus, which is consistent with "last started wins".
