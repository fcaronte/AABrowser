## 1. Current Status
- **Version / Milestone**: Post-2.2 Development Branch
- **Recent Updates**:
  - **Home network sites on Android 17 (Home Assistant, Proxmox, home proxy)**: two separate causes.
    - Apps targeting SDK 37 need the runtime permission `ACCESS_LOCAL_NETWORK` to reach LAN addresses (WebView included), otherwise the connection is blocked silently. Declared in the manifest and requested by `MainActivity.checkAndRequestAppPermissions()` together with the others (only on the phone: the car cannot show the system dialog). Docs: developer.android.com/privacy-and-security/local-network-permission.
    - Without `onReceivedSslError` the WebView cancels any invalid certificate silently (self-signed or issued for another name, typical of a reverse proxy reached by IP), where Chrome shows "Continue anyway". Now both WebViews ask: Main = `SslWarningPopup` overlay in the tab (background tabs wait until shown), Wide = `WideSslWarningScreen` (`MessageTemplate`, Cancel primary, back = cancel). The surface is only detached under a pushed template, so the WebView keeps waiting. `SslErrorPrompts` (one per WebView): one prompt at a time, requests with the same host:port + certificate SHA-256 join the open prompt, others are queued, all cancelled on page start / WebView release. Accepted certificates are remembered until the app is closed (`SslExceptions`, shared by Main and Wide); a different certificate on the same host asks again.
  - **Local player renamed "AAB Media", audio and video separated**: Audio / Video tabs (only when the folder has both, with counts) and separate queues: next/previous/shuffle/repeat/auto-advance stay in the queue of the playing file; switching tab only shows the other list, tapping a file there moves the queue. Startup reopens the tab of the last file. Videos: bigger stage (portrait 45vh, landscape panel 58% and height up to `100vh - 230px`), frame preview (`getScaledFrameAtTime` at 10% of the duration, max 30 s, 512 px JPEG) used as poster and as AA cover. Favorites still named "AABrowser Player" are renamed by `FavoritesRepository` (custom names untouched).
  - **Local media player of the app (`https://player.local/`, Main + Wide)**: replaces the poor test "Web Player" favorite (#11, migrated by URL in `FavoritesRepository`). Page in `assets/player/` (`index.html`, `player.css`, `player.js`), served by `LocalPlayer.intercept()` from both WebViews' `shouldInterceptRequest`:
    - `/api/library`: audio/video files of the folder remembered by `LastFileSelection` (subfolders included, max 5000); the page sorts them naturally (`Intl.Collator` numeric).
    - `/media/<id>`: the file, with `Range` -> `206 Partial Content` (fast start and seeking); `<id>` = base64url of the document id, rebuilt inside the granted tree.
    - `/api/tags/<id>`, `/api/art/<id>`: `MediaMetadataRetriever` title/artist/album + embedded cover (LRU caches). `MediaSessionManager` loads `player.local` covers through `LocalPlayer.artworkBitmap()` (no network).
    - Every data request needs the per-run token injected in the HTML (`window.AAB_PLAYER`): other sites in a tab cannot list/play the user's files; a 403 makes the page reload to get the new token.
    - Queue with shuffle, repeat all/one/off, previous (restart after 3 s)/next, resume of the last track and position (localStorage), tap on video = fullscreen, "Choose folder" (phone: system picker via the existing `webkitdirectory` flow; car: last phone choice).
    - Media Session (metadata + play/pause/next/previous/seekto) -> AA shows skip, title, artist and cover.
  - **YouTube saved speed**: the saved speed was applied only once per `<video>` element (YouTube reuses it for every video) and the 1.5 s poller saved any rate, including YouTube's reset to 1x on the next video, overwriting the preference. Now each new video (key = path + `v` + `currentSrc`) gets the saved speed when it starts (unless already ≠ 1x), only user changes are saved (`ratechange`, ignoring our own sets and resets of a not-yet-initialized video), rates go through the player API too (`setPlaybackRate`, menu stays in sync), music also detected by category `Music` (language independent).
  - **Input popup only for text fields**: `INPUT_LISTENERS_JS` opened the keyboard/mic popup on any `<input>` (sliders, checkboxes...); now only text, search, email, url, tel, password, number.
  - **Generic AA metadata from the page Media Session**: `syncMetadata` uses `navigator.mediaSession.metadata` (title, artist, artwork) before the site rules, and resends when only the cover changes.
  - **AA player: skip instead of ±10 s on track sites (Main + Wide)**: new `MEDIA_SESSION_TRACKS_JS` (in `getLifecycleAndMetadataScript`) wraps `navigator.mediaSession.setActionHandler` and stores only `nexttrack`/`previoustrack` in `window.aabMediaSessionHandlers` (play/pause untouched); when the page registers them it calls `AndroidBridge.updateMediaCapabilities(false, next, prev)`. Spotify and YouTube Music report skip from document start. `NEXT_SCRIPT`/`PREVIOUS_SCRIPT` call the page handler first (with `{action}` details), then Spotify's `control-button-skip-forward/back`, then ±10 s. YouTube video hosts keep the playlist logic; `checkYouTubeCapabilities` now skips `music.youtube.com`. The old hook had been dropped in `e913e8d` during a refactor (the scripts still checked `aabMediaSessionHandlers`).
    - The Spotify branch added in `abe34e3` used `url` inside the WebView factory (the URL the tab was created with): tabs that reached Spotify by navigation still seeked ±10 s, and the Wide was not covered. Removed (with `SpotifyManager.getNextScript/getPreviousScript`) in favour of the shared scripts.
    - Capabilities are no longer recomputed from the URL on `onPageFinished` / tab activation (they overwrote what the page reported); `MediaSessionManager.resetMediaState()` resets them on every page start, then `onPageStarted` sets the URL defaults (Spotify / YT Music / YouTube playlist -> skip).
  - **Wide fixed sidebar stealing page taps**: the hit test used `leftInsetPx()` + width + 20 px tolerance (x <= 74 px) while the sidebar is drawn at x 0..38 and the WebView starts at its edge, so taps up to ~36 px (7-8 mm at 119 dpi) inside the page hit home/back/search. Now the hit test uses the drawn bounds (`sb.left`/`sb.right`), with tolerance only towards the screen edge (`SIDEBAR_OUTER_TOUCH_TOLERANCE_PX`).
  - **URL vs search, same rule everywhere**: `UrlUtils.asUrlOrNull()` (new, used by `normalizeInput` in the Main and by the Wide `SiteSearch.resolve`, replacing `HomePage.asUrlOrNull`). Text with spaces is never an address (before, "10.000 passi" matched the local-network `10.` prefix).
  - **Startup crash fixed + file/folder picker for web pages (SAF, no storage permissions)**: new favorite #11 "Web Player" (`web-player.streamlit.app`, local media player in a srcdoc iframe with `<input webkitdirectory>` "Select Folder" and `<input multiple>` "Select Files", filters by file-name extension, plays via blob URLs).

    - Chromium WebView maps `webkitdirectory` to `MODE_OPEN_MULTIPLE` (`FileModeConversionHelper`) and expects the folder's descendant files, so the app cannot tell it from `multiple`: the input listener JS calls `AndroidBridge.onFolderInputClicked()` on click of a `webkitdirectory` input; the next `MODE_OPEN_MULTIPLE` request (within 1.5 s) opens `ACTION_OPEN_DOCUMENT_TREE` and returns the folder's files. `showDirectoryPicker()` arrives as `MODE_OPEN_FOLDER` (File System Access is enabled by WebView for targetSdk >= 36) and gets the tree URI.
    - File inputs no longer open the keyboard/mic input popup (`onStartInput`).
    - **Last selection reused** (`LastFileSelection`): phone and car pages are different WebViews and the system picker cannot open on the car, so on the car (Main `MainCarActivity` and Wide) any file request gets the last phone selection. The folder keeps a persisted read grant (survives restarts); single files stay in memory (readable while the phone Activity lives). On the phone, a folder request with a remembered folder shows "Last folder: X — Use it / Choose another" instead of the system picker, so a page reload no longer asks for the permission again.
  - **Tab close**: closing the active tab (tab bar or tab manager) now switches to the tab on its left (the new first tab if it was the first); the Dashboard opens only when no tab is left. Closing a tab on the left of the active one no longer shifts the selection to another tab (same fix for `removeWideTab`).
  - **Settings**: location permission request and restart fallback used `context as? Activity` (always null under `MainScreen`): now `LocalActivity.current`.
  - **Multi-tab Android Auto player: "last started playback wins"** (replaces the old close-tab/reload/navigate-home workaround):
    - Every WebView is now its own media client: each Main tab (`BrowserScreen`) creates its own `MediaSessionManager`, the Wide keeps its own. `MediaFocusManager` arbitrates between all of them.
    - When a playback starts in a client, that client takes the AA player; the previous owner is paused (PAUSE_SCRIPT) and detached, but its page is never closed, reloaded or sent to home.
    - Only the owner publishes metadata/state and receives AA commands (play/pause/next/prev/seek). With no owner, commands are ignored.
    - Selecting the "Wide:" tab in Main converts it in place into a normal Main tab (same id, same WebView, no reload); the Wide stays on its page.
  - **Root causes fixed** (why hooking the player was unreliable):
    - The JS bridge and WebViewClient in `BrowserScreen` are created once in the `AndroidView` factory, so they captured a frozen `isTabActive`: tabs created in background never reported media, tabs created active kept reporting from background. Now read through `rememberUpdatedState`.
    - A single shared Main `MediaSessionManager` had `onPlay/onPause/...` bound to the last created WebView, so AA commands could reach the wrong tab.
    - Bridge calls ran on the JavaBridge thread; the delayed (500 ms) PLAYING could be published after a later pause or after another client took focus. Now all state changes run on the main thread, the pending PLAYING is coalesced, re-checked and cancelled on focus loss.
    - Metadata updates no longer force STATE_PLAYING (a paused page stays paused on AA).
  - **Self-pause right after a playback starts (page change) fixed**: `CarMediaService` called `requestAudioFocus()` on every metadata update (and on AA play). The WebView (Chromium `AudioFocusDelegate`) already holds audio focus while playing, so the service stole it and Chromium paused the video ~1 s after it started (seen in logcat: WebView requestAudioFocus -> service requestAudioFocus -> `onAudioFocusChange(-1)` to `AudioFocusDelegate` -> page `pause`). Same fix as commit `bd244ca` ("fix spotify auto pause"), which had been undone by `3053222`.
  - **YouTube tap-to-seek (Main + Wide)**: the m.youtube.com player (2026: `div.ytPlayerProgressBarDragContainer[role=slider]`, 44 px tall) seeks only by dragging; a tap on the bar is ignored (reproduced with Chrome 155 headless, same UA/viewport as the car WebView: 1075x514 CSS px, dpr 0.744). New `YouTubeManager.getTapToSeekScript()`, injected by `WebViewScriptRouter` for YouTube: a still tap inside the visible bar seeks to that point (skips overlapping buttons, ads, live streams). Drags are untouched (no preventDefault/stopPropagation). In the Wide dragging is still impossible: the Car App Library `onScroll` gives only distances, no finger position, and is converted to page scroll.
  - **YouTube voice search (Wide)**: m.youtube.com voice search does not use `SpeechRecognition`; it records with `getUserMedia({audio})` (checked in the ytmweb bundle). The Wide `onPermissionRequest` granted only `RESOURCE_PROTECTED_MEDIA_ID`, so the mic was denied (`NotAllowedError`). Now it also grants `RESOURCE_AUDIO_CAPTURE` (camera still denied); the Main already granted it.
  - **Wide keyboard re-enabled (⌨️ in the input popup)**: the old flow injected the text into `document.activeElement` after the full-screen `SearchTemplate` closed, but meanwhile the page loses focus (`activeElement` = BODY), so the text went nowhere. Now `openFieldInput()` first runs `BrowserJavascript.getCaptureInputTargetScript()` (stores the field in `window.__aabTypingTarget`, returns value/hint; password values never returned), opens `WideSearchScreen` prefilled (`initialText`, `allowEmpty`), then `getSetInputTextScript(text)` re-focuses that field, sets the value with the native setter (React-safe) + `input`/`change`, and submits only search fields (`form.requestSubmit()` or Enter). Tested in local Chrome 155 (WebView UA): YouTube search after blur -> `/results?search_query=...`; login field typed, not submitted. The popup is suppressed for 1.5 s after typing (`INPUT_POPUP_SUPPRESS_MS`). A docked "bottom" keyboard like the Main's is not available to Car App Library apps (only full-screen `SearchTemplate`/`SignInTemplate`); the Main uses the projected SDK `InputManager`, which template apps cannot use.
  - **Wide double-tap-zoom block on YouTube**: `getDisableDoubleTapScript()` used `style.innerHTML`, blocked by YouTube's Trusted Types ("This document requires 'TrustedHTML' assignment" in logcat), so the style never applied there. Now uses `style.textContent`.

## 3. Architectural Decisions
- **Invalid certificates: always ask, never proceed silently**: `handler.proceed()` only after an explicit user choice, remembered per host:port + certificate fingerprint and only in memory (closing the app forgets it). Never accept all errors globally: it would make every site open to interception.
- **SDK 37 local network**: any new feature that talks to LAN devices (WebView pages, sockets, mDNS) depends on `ACCESS_LOCAL_NETWORK`; it can be granted only from the phone UI.
- **Local player queues are per kind**: audio and video never share a queue; the playing file's kind decides next/previous, the visible tab is only a view.
- **Local player = web page of the app, not native**: same page in Main and Wide, video needs the WebView anyway, AA integration comes for free from the injected scripts (media listeners, Media Session). Files are served by the app (no blob URLs): seeking works, nothing to re-select after a reload, works on the car without a picker.
- **Page buttons must not be named "Play"/"Pausa"/"Riproduci"...**: `PLAY_SCRIPT`/`PAUSE_SCRIPT` click buttons by those labels/classes after toggling the media themselves, so a toggle button with such a label would undo the AA command (the player page uses icon-only `#playToggle`).
- **Who decides the AA player buttons (skip vs ±10 s)**: the URL gives only the defaults at page start (`onPageStarted`); after that the page is the source of truth (Media Session `nexttrack`/`previoustrack`, YouTube playlist check). Never recompute from the URL later in the same page, and never in WebView factory callbacks with the composable `url` (it is the URL the tab was created with).
- **Below `MainScreen`, `LocalContext` is not the Activity**: use `LocalActivity.current` (re-provided by `MainScreen`), never `LocalContext.current as? Activity`, and `LocalActivityResultRegistryOwner.current` may be null (Android Auto `MainCarActivity`).
- **Web file chooser contract**: the `ValueCallback` must be completed exactly once. Either call it and return true, or return false without calling it (the WebView then cancels by itself); doing both crashes with "Duplicate showFileChooser result". Only SAF intents are used, so no storage permission is needed.
- **Per-WebView media clients + single arbiter**: `MediaFocusManager` is the only place that decides who owns the AA player; `MediaSessionManager` instances never talk to each other.
- **Who can take the player**: a client claims it only on a real start (JS `play` event / unmute, or a paused→playing transition) and only if it can take focus (visible Main tab or the Wide). Background tabs that start by themselves (autoplay, wide mirror tab) are paused.
- **Stale reports never claim**: periodic updates (`timeupdate`, Spotify polling) from a non-owner that was already playing are treated as late reports and paused (rate limited to 1/s).
- **Focus release**: on page start, tab close, Wide surface/WebView release. The owner sends STATE_NONE + empty metadata so `CarMediaService` goes back to weather/idle.
- **Injected JS must be Trusted Types safe**: YouTube enforces `require-trusted-types-for 'script'`, so never assign strings to `innerHTML`/`outerHTML`/`insertAdjacentHTML` in injected scripts (use `textContent` / DOM APIs).
- **Never request Android audio focus from the app side** (`CarMediaService` or elsewhere): each WebView requests it through Chromium when its media really starts; any other request from our package takes it away and Chromium pauses the page. The WebViews also pause each other natively through audio focus, which is consistent with "last started wins".
