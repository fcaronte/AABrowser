\## 2. Project Overview & Architecture

\*\*AABrowser\*\* is an Android web-browser application designed specifically for \*\*Android Auto\*\*. Its core goal is to provide a seamless, touch-friendly, and responsive web browsing experience on head units using native templates and custom WebView interactions.

\### Primary Tech Stack & Structure

\- \*\*Language\*\*: Kotlin / Android SDK

\- \*\*Dependency Management\*\*: Centralized via \`gradle/libs.versions.toml\` (version catalog)

\- \*\*CI/CD\*\*: GitHub Actions workflows for automated APK compilation and release generation

\- \*\*Logging\*\*: Uses custom \`AppLog\` utility to strip/sanitize sensitive user data from logs prior to export or sharing

\- \*\*Updater/Installer\*\*: Updates are automated via \`DownloadManager\` + \`FileProvider\` and targeted for installation through \*\*KingInstaller\*\* (\`com.example.kinginstaller\`, opened on its MainActivity, which loads the file and lets the user choose how to install; the APK is downloaded into the app's own external folder, because the public Downloads are not readable by the app)

\- \*\*GitHub repository name\*\*: the repository is \`fcaronte/AABrowser\`, to be renamed \`fcaronte/CarWeb\` a few days after the release that knows both names (the package name stays \`com.fcaronte.aabrowser\`: another one would need a reinstall). \`GitHubRepo\` (\`utils/GitHubRepo.kt\`) is the only place that knows the names: updates are looked up on \`CarWeb\` first and then on \`AABrowser\` (it answers 404 until the rename), APKs of either name are accepted by \`isOfficialReleaseUrl\` (the check KingInstaller depends on), and the links the app opens (GitHub icon, README) and the identification sent to Radio Browser, Apple and LRCLIB use the name that answered last (the old one until it is known: it works before the rename and, through GitHub's redirect, after it). Versions before this one only know \`AABrowser\`: after the rename they cannot download an update by themselves (the address GitHub gives has the new name) and need one manual install. Never replace \`kododake/AABrowser\` and \`slashmax/AABrowser\` (the projects CarWeb comes from, credited in the README and in \`BrowserJavascript\`). When no installation knows only the old name any more, drop it from \`GitHubRepo.NAMES\`.

\### AABrowser Widescreen (Wide Mode)

\- \*\*Concept\*\*: Native Android Auto template-based UI (inspired by apps like Xtream Player) occupying the primary screen space (navigation/map area).

\- \*\*Layout Logic\*\*:

  - Supports Full Screen and Split View modes.

Not tried in the car.
  - One layout (since 2.8, no "fixed menu" setting): the dock, a sidebar on the left side, always built from the user's choice of `SidebarAction` buttons (back, forward, home, reload, search, AdBlock shield, desktop, voice, favorite = add the open page, share = the page's QR code on a card, settings when its page exists, exit; order and visibility in Settings, Home cannot be hidden; each button that needs a web page looks off on the home). The only button Android Auto needs at the top right shows or hides the dock and, with a phone app (Shizuku) open, its own bar too; the bottom strip keeps only PAN. The Main can show the same dock (`AppSettings.mainDock`, Settings > Sidebar in CarWeb): the round menu button then opens and closes it instead of the radial menu (`NavigationOverlay` `dockMode`, `MainDock`, the page and the apps keep clear of it).

  - \*Hard Constraint\*: Android Auto stock template framework enforces that the right stock bar MUST keep at least one action button locked at the top-right corner.

  - \*Android Auto Limitations\* (set by Google for Car App Library apps, not bugs; the "Beta" label was dropped in 2.4): Only the full-screen Android Auto keyboard is available for text fields (Car App Library apps cannot show a docked keyboard; Android Auto may lock it while driving); since 2.5 the optional Passenger keyboard (drawn by the app: QWERTY, plus AZERTY, QWERTZ, Russian and Arabic with the 🌐 key for those languages) replaces it in both apps. Double-tap-to-zoom is disabled and drag gestures are not available (the host gives no finger position), for touch stability and safety while driving.

\### TV in CarWeb Media (2.5)

\- Page `https://player.local/tv` (assets/player/tv.html, tv.js, tv.css), reached from the TV button of CarWeb Media. `IptvSources` adds the IPTV-org language playlist automatically as the first, non-removable source (`languages/<ISO-639-3>.m3u`, selected from the app locale); unsupported languages use `index.m3u`. User M3U lists can be entered as URLs or selected as local M3U/M3U8 files in Settings on the phone (section "TV, Radio e Podcast", `IptvSourcesCard`); Xtream accounts are also added there (`iptv_sources`, out of the backup). The last entry of the list menu (`assets/player/lists.js`) asks the app (`AndroidBridge.openMediaLists`): on the phone Settings open on that card, in the car (no bridge answer) the page says to do it on the phone. When the lists change the app tells the open pages (`aabSourcesChanged`): the menu updates and playback goes on. Local files use a persisted Storage Access Framework read grant. For Xtream, server + user + password or the full link that contains them (`XtreamLink`). The app reads the lists (`IptvLibrary`) and proxies every stream (`IptvProxy`): the page only gets random ids, never addresses or credentials (Xtream puts user and password in the stream URL), and HLS playlists are rewritten so segments go through the proxy too. Playback with hls.js (full build: the light one has no separate audio tracks, about a third of the channels) and mpegts.js, Apache 2.0, bundled in assets/player/lib with their licenses. Headers asked by the lists (`#EXTVLCOPT`, `#EXTHTTP`, `#KODIPROP`, `url|User-Agent=…`, `IptvHeaders`) go with the proxied requests, segments included. DASH is not supported (most listed `.mpd` no longer answer). Never log stream addresses. Favorites (★) are one list for all the lists: each channel keeps its list (`s`) and plays from it without switching the list in the menu; favorites of a removed list are hidden, not deleted (they come back with the list). The per-list favorites saved up to 2.6 are merged at the first opening.

- Fullscreen channel strip (15/11/2026, user: "al posto del cambio canale piccolo la barra che mostra più canali così che posso saltare direttamente a quello che mi interessa"; it replaced the small panel of 14/11): in fullscreen (the `.stage`) a tap on the video also shows, at the top, a panel (`.zap` in tv.html and tv.css) with a row of channel chips (`.zap-strip`, `.zap-chip`: logo and name, the one on air highlighted and centred), on each side ⏮ ⏭ (`step(±1)` over the list shown, like the buttons under the video and the Android Auto player) and, when there is room, two page buttons that scroll the row by a page without changing channel (`zapStart`, `pageZap`), and a status line (loading, channel unavailable: the page's `#message` sits outside the fullscreen element and cannot be seen). A tap on a chip plays that channel and `zoom.keepBar()` restarts the 4 s. The chips are one every ~128 px, from 3 to 9 (`zapCount`; up to 520 px wide the page buttons are hidden); they are `div role=button`, never `<button>` and never with "play" in a class name (the generic Android Auto scripts click buttons by label). In the Wide the panel stops short of the host's top-right button: the app puts the class `in-wide` on the root element at document start (`WideScreen.IN_WIDE_SCRIPT`, a MutationObserver because the root does not exist yet) and the CSS leaves `--host-end` (96 px); the same class does it for the bars of the Media pages and of Other Apps. The strip lives inside the fullscreen element because Chromium makes the rest of the document inert; it shows and hides together with the zoom bar (`video-zoom.js` puts the class `bar-shown` on the stage; `attach` returns `toggleBar` and `keepBar`) and only in fullscreen. A channel that does not start has no video: `isVideo` is also true in fullscreen with a channel selected, and a tap on the cover (`.art`) toggles the bar, so you can zap away from a dead channel without leaving fullscreen. Checked in headless Chrome with the real page and a mock API (1075x514 and 390x844; harness `/tmp/aab-videofit-test/tvstrip.mjs`: counts, pages, a tap on a chip, the current one centred, no overflow, the Wide margin).

- Auto-resume of TV (`assets/player/recover.js`, `AABRecover`, a pure decision module with `recover.test.js`): if the user did not pause, the page keeps trying by itself. Once a second tv.js tells it how the video is and it answers nothing, `play()` or "restart" (load the stream again, like changing channel and coming back) with growing waits (1.5, 3, 6, 12, 20 s, then every 30 s; they start over after 3 s of real playback). Paused without being asked (focus lost, signal) = a `play()` after about 1.5 s, again every 3 s, and a restart if it stays still for 10 s; "playing" with the time not moving = a restart after 10 s (25 s at the start: a slow channel); a stream error (hls.js, mpegts.js, `<video>`) or `ended` (a live stream that ends is a dropped one) = a restart after the wait. **A pause the user wanted is never undone**, and it is told by the hooks of the app's own scripts (`window.aabMarkUserPause` / `aabMarkUserPlay`, called by `PAUSE_SCRIPT`, `STOP_SCRIPT` and `PLAY_SCRIPT`: Android Auto player, wheel keys, voice, another playback that took the player) and by the page's own pause paths (`userPause()`: button, Media Session, voice), never by the `pause` event, which a lost focus produces too. tv.js wraps the two hooks with `Object.defineProperty` (the app's function stays and still runs, whichever script defines it first). If another app plays on the phone or a call is on (`AndroidBridge.otherAudioPlaying()`, answered only to the app's pages in the Main and the Wide: `VirtualAppAudio.otherAudioPlaying`, i.e. `AudioManager.mode` not normal or an active media/game/unknown player) the page does not take the audio away: it waits and resumes when that ends. Radio and Podcast do not have it (the Radio page reports stalls, see below). Checked in headless Chrome with real timings (system pause, pause and play through the app's hooks, the page's buttons, another app playing, a frozen stream, a stream that ends, a broken channel with growing waits that stop when the channel changes); not tried on a device or in the car.
- Favorites always in view (TV, Radio, Podcast): a round ★ button beside the search field (`.search-row`, `#favoritesToggle`, styles in tv.css, which the three pages share), no longer a chip scrolling away among many categories. TV: on = the favorites of every list, off = back to the category that was open; Radio: favorites of every list / all stations; Podcast: followed shows / all shows (inside an open show the button is hidden and «‹ title» and Follow stay). An element whose `display` is set by a class needs its own `[hidden]` rule, or the attribute does nothing (`.favorites-toggle[hidden]`). With no favorites the open list says what to do (`tv_no_favorites`, `radio_no_favorites`, `podcast_no_followed`; in TV only in the page, not in the fullscreen channel panel, which has its own status).

\### Split View: Browser and Phone App Side by Side

- Il primo tasto della barra dell'app (Main e Wide) e un'impostazione («Schermo diviso con il browser», `virtual_split_enabled`) mettono il browser e l'app del telefono uno accanto all'altro (`VirtualSplit`, modello senza Android con i suoi test): **65/35 di serie, all'app il 35%** (era 70/30 fino al 15/11/2026), da 20% a 50% a passi di 5 (`AppSettings.virtualSplitFraction`) e sul lato scelto (`virtualSplitSide`, destra di serie); `virtualSplitEnabled` si ricorda. **Niente trascinamento** per cambiare la dimensione (nella Wide l'host non dà la posizione del dito): si sceglie solo nelle Impostazioni. Spento, tutto come prima: l'app a schermo intero con la barra accanto (la barra sopra l'app e la sua impostazione non ci sono più).
- **Il display dell'app è sempre in verticale nel pannello**: ha la forma della vista (`VirtualAppTab` e `WideVirtualApp` danno la misura del pannello, `VirtualSplit.displayWidth`: un pannello già stretto lo riempie, uno largo, 50% di uno schermo molto largo, lascia bande nere e il display, alto quanto il pannello, sta in mezzo). Non si scambiano larghezza e altezza: il display deve avere la forma della vista che lo mostra, altrimenti l'immagine e i tocchi si deformano. A schermo intero il display segue la vista (in orizzontale sull'auto, in verticale su un telefono in piedi). **Densità limitata** nel pannello (`VirtualSplit.density`, `VirtualAppSession.splitMode`): l'app vede almeno 320 dp di larghezza come su un telefono stretto, perché un pannello stretto a densità piena avrebbe un'app impaginata male.
- **Main**: con un'app scelta e lo schermo diviso acceso, `MainScreen` mette la scheda dell'app nel suo pannello e, nell'altro, il browser: l'ultima scheda web usata (`lastWebTabId`, altrimenti la prima; senza schede web si apre la pagina iniziale in secondo piano). La scheda accanto all'app sta sopra le altre schede in secondo piano e conta come scelta per `BrowserScreen` (riproduzione, schermata, tocchi) ma non per quello che dipende davvero dalla scheda attiva (Indietro e ricarica restano dell'app, `isFullScreen` non cambia: un video a schermo intero nel browser riempie il suo pannello). Il dock aperto resta sul bordo e i pannelli si dividono lo spazio che resta. **Lo schermo diviso resta** (15/11/2026, prova dell'utente: «devo cliccare su un'altra pagina e poi tornare a quella dell'app in piccolo e poi si vedono»): `splitAppId` è la scheda dell'app attiva o, guardando una scheda web, l'ultima scheda app aperta (`lastAppTabId`, finché esiste); i due pannelli restano finché lo schermo diviso è acceso, anche cambiando scheda (il browser è la scheda attiva se è web, altrimenti l'ultima web). Chiusa la scheda dell'app, lo schermo diviso finisce.
- **Wide**: la vista dell'app è il solo pannello (`WideScreen.layoutVisibleArea` divide la regione sotto i tasti di Android Auto e a destra della sidebar con `VirtualSplit.panels`; il confine è lo stesso per pagina e app) e la pagina resta visibile e toccabile nell'altro. \### Bluetooth Mouse and Keyboard: Controlling the Car Screens

- Un mouse e una tastiera Bluetooth collegati al **telefono** comandano gli schermi dell'auto (la Main e la Wide). Con Android Auto davanti sul telefono gli eventi non arrivano a CarWeb, quindi serve una schermata da lasciare aperta: `BtInputActivity` (Impostazioni > Altre App > «Mouse e tastiera Bluetooth» > «Apri la schermata di controllo»: solo dal telefono, nel ponte della pagina è l'azione `bt_input`, in auto il pulsante dice di farlo dal telefono; `AppSettings.btPointerSpeed`, 50-300% a passi di 25, è nella stessa scheda). Nera, luminosità al 20%, schermo acceso (`FLAG_KEEP_SCREEN_ON`) e anche sopra il blocco schermo (`setShowWhenLocked`): dopo 8 s senza un tocco la scritta sparisce e la luminosità scende al 2%, come un telefono bloccato ma in ascolto (con lo schermo spento il sistema non dà gli eventi a nessuna app); dice quale schermo dell'auto riceve (riletto ogni mezzo secondo); Indietro o Chiudi escono, un tocco riprova a catturare il mouse. Non esportata, `singleTop`, fuori dai recenti. Il popup ⌨️ 🎤 dei campi di testo non compare finché è aperta (`BtInputRouter.capturing`: Main e Wide).
- **Cattura**: `View.requestPointerCapture()` sulla vista radice (serve il focus della vista e della finestra: si chiede a ogni `onWindowFocusChanged(true)` e al tocco) e `OnCapturedPointerListener`: movimenti relativi (le mosse raggruppate in un evento si sommano con la sua storia), pulsanti (differenza di `buttonState` rispetto all'evento prima: `BtInput.changes`) e rotellina (`ACTION_SCROLL`, assi `HSCROLL` e `VSCROLL`). Un touchpad catturato dà posizioni assolute del pad: da quello si prendono solo i pulsanti. I tasti arrivano con `dispatchKeyEvent`; restano al telefono quelli del telefono e i multimediali (`BtInput.forwardable`: Indietro, Home, Recenti, accensione, volume, fotocamera, chiamate, assistente, play/pausa/avanti/indietro: il volante e le cuffie non perdono la loro strada).
- **Smistamento** (`BtInputRouter`, solo thread principale): un puntatore solo, nelle coordinate dello schermo che lo riceve (parte dal centro, si ferma ai bordi, `BtInput.moved`). Ogni schermo dell'auto si registra come `Target` e riceve se `isInFront()`: la Main (`ui/MainBtTarget.kt`, registrata in `MainCarActivity` a onResume e tolta a onPause) è davanti e la Wide (`WideScreen.btTarget`) è davanti, e **nessuna delle due è coperta dall'avviso di guida**: in movimento senza la Modalità passeggero il mouse e la tastiera non passano sotto la copertura. Il puntatore sparisce dopo 8 s senza muoversi (`BtInput.CURSOR_HIDE_MS`).
- **Mouse**: pulsante sinistro = un dito; destro e laterale «indietro» = Indietro; laterale «avanti» = avanti; rotellina = scorrimento (56 dp per scatto, `BtInput.WHEEL_STEP_DP`); il centrale non fa niente. Main: tocchi veri (dito, touchscreen, quelli dell'auto: premere, trascinare, lasciare) alla radice della finestra dell'auto (`decorView.dispatchTouchEvent`), quindi li ricevono le pagine, Compose e le schede delle app del telefono sullo schermo virtuale; la rotellina è un `ACTION_SCROLL` di un mouse (`dispatchGenericMotionEvent`); il puntatore si disegna in Compose (`BtCursorOverlay`, sopra a tutto, `zIndex` 101, con l'origine della vista tolta dalle coordinate della finestra). Wide: il clic è `onClick(x, y)` nel punto in cui si è premuto (quindi passa da tutto quello che la Wide già sa fare: sidebar, app del telefono, schermo diviso, video a schermo intero), un trascinamento oltre `BT_CLICK_SLOP_DP` (8 dp) scorre come un dito (`onScroll`), la rotellina è `onScroll`; il puntatore è una vista in cima alla superficie (`BtCursorView`, spostata con `translationX/Y`, non prende tocchi).
- **Tastiera**: i tasti rapidi sono quelli dei browser per computer (`BtInput.shortcutFor`, con i test): Esc e Alt+← indietro, Alt+→ avanti, F5 e Ctrl+R ricarica, Ctrl+L, Ctrl+K e F6 ricerca, Ctrl+Tab e Ctrl+Pag↓ scheda dopo, Ctrl+Maiusc+Tab e Ctrl+Pag↑ scheda prima, Ctrl+W e Ctrl+F4 chiudono la scheda, Ctrl+T ne apre una, Alt+Home la home. Si eseguono alla pressione; le ripetizioni e il rilascio dello stesso tasto non arrivano alla pagina. Ctrl+A, C, V, X, Invio, Tab e gli altri tasti vanno alla pagina o al campo con il focus. Main: `BtShortcuts` (un flusso che raccoglie `MainScreen`; `stepBack` è lo stesso passo indietro del tasto Indietro del telefono, condiviso: pagina precedente, home, poi le schermate da cui si veniva; sulla home non fa uscire) e i tasti normali a `decorView.dispatchKeyEvent` (serve il focus di una vista: dopo un clic sulla pagina, che lo prende da sola). - **Non provato** su un telefono né in auto (15/11/2026): la cattura del mouse e dei tasti, il disegno del puntatore, i tocchi dalla radice della finestra dell'auto della Main, la rotellina nella Main e soprattutto i tasti nella Wide (ora con JavaScript, ma mai provati sull'auto). \### Local Player: Video Without Sound

- Il motore della WebView decodifica il video con il MediaCodec del telefono e l'audio con i suoi decoder: AC-3, E-AC-3 e DTS (film, registrazioni) no, e su molti telefoni (i Pixel) il sistema non ha nemmeno un decoder Dolby: il video parte e tace. `/api/tracks/<id>` (`MediaExtractor` + `MediaCodecList`) dice la prima traccia audio e video del file e se c'è un decoder; `player.js` `checkSound()`, 3 s dopo l'avvio senza audio decodificato (`webkitAudioDecodedByteCount`), mostra «L'audio di questo video (AC-3) non si può riprodurre qui» o «Questo video non ha una traccia audio». Quando il formato è noto il messaggio aggiunge il suggerimento `player_other_apps_hint` (aprire il file con l'app che si usa di solito sul telefono, dalle Altre App, che la mostrano sullo schermo dell'auto) e resta 15 s invece di 9; senza traccia audio non c'è niente da suggerire. Per decodificarlo servirebbe un decoder software (Media3 con estensione FFmpeg, oppure libVLC): non fatto.

\### Radio in CarWeb Media

\- Quando cambia il titolo fornito dallo stream, la pagina cerca automaticamente i testi su LRCLIB e li rende disponibili dal pulsante Testi; i risultati sincronizzati sono mostrati senza evidenziazione temporale perché la riproduzione può iniziare a metà brano.
\- Il testo della stazione passa da `assets/player/track-parser.js` (brano in onda, non il successivo; formati `Titolo~Artista~…`, `Song*…`, `text="…" song_spot="M"`; nome della stazione, indirizzi, pubblicità, telefoni). Test: `node --test browser/src/test/js/`, con testi veri campionati da Radio Browser.
\- Se la stazione non invia metadati, il titolo può essere cercato manualmente.
\- Page `https://player.local/radio` (assets/player/radio.html, radio.js, radio.css), linked beside TV in the local player. Station data and stream selection use Radio-Browser.info; the native API keeps stream URLs out of the page until playback is requested, tracks station clicks, and rejects non-public stream hosts. The country follows the app's explicit locale region, or a language-based default (first list, not removable); other Radio Browser countries and the user's M3U lists (URL or file) are added in Settings (`IptvSources.Section.RADIO`) and chosen from the menu at the top. Stations of a user list get an id derived from their address, play like the TV lists (no public-host check) and favorites work across lists. Search, per-station favorites, HLS playback (using the bundled hls.js), and Android Auto Media Session controls are supported. Verify network/provider compatibility on a real device; some stations may be unavailable or use codecs unsupported by WebView.
\- Animated visual effects, as in the music player: the button `#effects` next to the controls opens a choice (`#optionsSheet`: off, bars, wave, circle; saved in the page state as `effect`). The drawing is `assets/player/effects.js`, shared with `player.js` (`AABEffects.attach`: canvas, chosen effect, when to draw, the analyser); each page owns its audio graph. The AudioContext is created with a tap (without a gesture it stays suspended and the audio would be silent) and the element is wired to Web Audio (`createMediaElementSource`, for good: it cannot be undone) only when its source is of the page's own origin: a stream of another site without CORS, wired to Web Audio, gives only zeros and the element goes silent (measured in Chrome: peak 0). So with the effects on, and for ever once the element is wired, `/api/radio/play` gets `proxy=1` and direct streams go through the app's proxy (`RadioApi.viaProxy`, `IptvProxy`, `/tv/stream/<id>`); HLS stays with hls.js (a MediaSource of the page). Choosing an effect while a direct stream plays restarts the station through the proxy (a moment of pause). A saved effect is applied from the first tap after the page opens. Through the proxy a progressive stream is served as `IptvProxy.LiveStream` (declared length `Int.MAX_VALUE`, `skip` consumes nothing): the WebView takes `available()` of the response as the file length and the media element ends exactly there, so with the buffer-sized length every station ended after about 2 s (seen in the phone log of 15/11/2026; the headless tests could not show it, Node answers like a real server). A proxied stream that still ends before 120 s with the effects on makes the page turn them off, reload and resume the station directly (`proxyFailed`, flags in `sessionStorage`). The URLs refresh by themselves: every play asks Radio Browser `/json/url/<uuid>` (the cached list entry only if that fails). Tests: `effects.test.js`, `RadioApiTest`; headless Chrome with the real Radio and Music pages and a mock API (stream of another origin without CORS, HLS, reload of the page).
\- Stazioni che non partono o si fermano (15/11/2026): Radio Browser dà per buona una stazione (`lastcheckok`) quando il server risponde e manda un po' di audio, ma ce ne sono che non rispondono mai (`streamingv2.shoutcast.com`) e altre con la sorgente ferma, che a ogni collegamento rimandano la stessa scorta di audio (una decina di secondi, «sempre lo stesso pezzo») e poi niente. La pagina lo dice: se il primo suono non arriva entro 20 s «Stazione non disponibile», se a stazione partita il tempo di riproduzione resta fermo per 8 s (non in pausa) «Nessun audio dalla stazione» (`radio_stalled`), che sparisce da sola quando l'audio riprende (`START_TIMEOUT_MS`, `STALL_MS`, `watchStart`, `checkProgress` in `radio.js`). Provata in Chrome headless con la pagina vera e stazioni finte (sana, ferma, muta, a scatti).

\### Settings: One Page for Main and Wide

- Le Impostazioni sono **una pagina sola**, `https://player.local/settings` (`assets/player/settings.html|js|css`), al posto della schermata Compose (tolta): la Wide la carica come ogni pagina (tasto ingranaggio del dock, tasto della home), la Main la mostra a tutto schermo in una WebView sua (`SettingsWebScreen`, non una scheda: niente voci in più nella barra delle schede; Indietro chiude prima un riquadro aperto nella pagina, poi esce). La WebView non carica altro che le pagine dell'app (tutto il resto riceve 403) e il suo ponte `AndroidBridge` ha solo `isPhone()` e `run(azione)`.
- **Guidata da uno schema**: `SettingsSchema` (sezioni, schede e righe con l'id del testo, la chiave del valore e le condizioni `showIf` che la pagina ricontrolla da sola: la scelta del tema compare accendendo «forza il tema» senza un giro con l'app) e `SettingsApi` (`/api/settings/get|set|do|qr`, token come le altre pagine): i valori di ora (`values`), gli elenchi (`data`: preferiti e app per la pagina iniziale, tasti, liste, siti con permessi, cosa cancellare), come si scrive ogni chiave (`registry`: valori controllati, mai altro che quelle chiavi) e le azioni dei pulsanti (`act`). La pagina non conosce nessuna voce: disegna quello che riceve, nella lingua dell'app, anche i colori (`theme`, si aggiornano a ogni cambio di tema). Sezioni che si aprono e si chiudono, schede con il bordo leggero, interruttori come quelli di Material; le scelte con nomi lunghi (motore di ricerca, qualità di YouTube, pagina iniziale) sono elenchi che si aprono, chiusi di serie, non pulsanti affiancati (`Choice` senza `buttons`); **− e +** al posto dei cursori (nella Wide non si trascina); riquadri nella pagina (avviso della Modalità passeggero, novità, codice QR dei link in auto) al posto delle finestre di sistema, che sullo schermo dell'auto non si vedrebbero; avvisi brevi in basso. Le richieste partono una dopo l'altra e la pagina mostra lo stato dell'app solo quando non ne aspetta altre (due tocchi di fila sul + non tornano indietro).
- **Solo sul telefono** (`SettingsPhoneActions`, composto dove c'è l'ActivityResultRegistryOwner: la Main sul telefono): aprire un link (README, GitHub, PayPal, caffè: in auto la pagina mostra il codice QR, `/api/settings/qr?link=<id>`, mai un indirizzo dato dalla pagina), il log da condividere (pressione lunga sul logo GitHub), la lingua dell'app, il permesso della posizione per il meteo, il backup (selettore di file; l'importazione chiede prima un secondo tocco), i file M3U e OPML e le finestre per scrivere indirizzi, server Xtream con utente e password, feed RSS, Paese e indirizzo di una lista dei siti pubblicitari (`SettingsNativeDialogs`). **Indirizzi e password restano in quelle finestre e vanno dritti all'app: la pagina riceve solo nome e tipo delle liste.** In auto e nella Wide la pagina dice di farlo dal telefono. Il riavvio (lettore multimediale, meteo, ripristino del backup) lo chiede la pagina al ponte; nella Wide, che non ha il ponte, dice di riavviare l'app.
- Aperta da una pagina di TV, Radio o Podcast («Aggiungi una lista…») la sezione delle liste è aperta e quella lista in vista (`?focus=tv|radio|podcast`). I preferiti ripristinati o completati dalla pagina avvisano il ViewModel della Main (`FavoritesRepository.externalChanges`). Test: `SettingsSchemaTest` (ogni riga ha chi la scrive e ogni chiave una riga, gli elenchi che la pagina chiede ci sono, i testi esistono in tutte le lingue con gli stessi segnaposto) e `settings.test.js`; provata in Chrome headless con un finto server (con e senza ponte del telefono, conferme in due tocchi, riquadri, due tocchi veloci sul +), non sul telefono né in auto.

\### Backup

- Impostazioni > Esporta/Importa (`ui/BackupCard.kt`, `BackupRestoreUtils`, formato 2 con il tipo di ogni valore), solo sul telefono: il file si sceglie con il selettore di Android, quindi si rilegge anche dopo una reinstallazione o su un altro telefono (un file lasciato in Download da un'altra installazione non si legge più). Dentro: `BOOKMARKS`, `aa_browser_settings`, `adblock_prefs`, `site_permissions`, `iptv_sources` (liste con indirizzi e password: solo nel file, mai nel backup di Google) e `media_pages`; fuori certificati accettati, cartella scelta per i file e aggiornamenti. Dopo il ripristino l'app si riavvia. Si leggono anche i file di prima (solo preferiti e impostazioni).
- Lo stato delle pagine di TV, Radio e Podcast (preferiti, seguiti, punto d'ascolto, ultima lista; le copertine no) sta nel localStorage della pagina, fuori da ogni backup, e in copia nell'app (`MediaPages`, `assets/player/store.js`, `/api/pages/save` col token, 10 s dopo un cambio o quando la pagina si chiude): all'apertura vale la copia dell'app (`config.saved`). Niente indirizzi né password, quindi va anche nel backup di Google.

\### Phone Back

- `PhoneBackHandler` (tasto o gesto; in auto non fa niente, `MainCarActivity` non ha il dispatcher): prima chiude quello che è aperto sopra (riquadri della pagina, ricerca, menu radiale, modifica dei preferiti), poi la pagina precedente della scheda, poi la home; sulla home il primo indietro mostra un messaggio e per 3 s il gestore si spegne: il secondo lo fa il sistema ed esce dall'app. Mai chiudere il processo: ci girano anche le app dell'auto. Un nuovo riquadro a tutto schermo deve avere il suo `PhoneBackHandler`.

\### Voice Commands in CarWeb Media

\- `VoiceCommands` capisce le frasi (11 lingue) e decide la pagina; `MediaVoice` tiene la richiesta e la pagina la viene a prendere (`/api/voice`, con il token) quando si apre o quando l'app la avvisa: niente parametri nell'indirizzo, così nessun sito può far partire qualcosa e ricaricare non ripete il comando. `MediaMatcher` (Kotlin, con test) trova i nomi per TV, Radio, Podcast e file.

\### Player Card Tap

\- Android Auto manda il tocco sulla scheda del player al componente che la sessione scrive nell'extra `android.media.session.BROWSE_SERVICE`, se è nel suo menu; senza, alla prima app del pacchetto nel menu: la Wide, che è di categoria navigazione e prende il posto del navigatore aperto. L'opzione "Il tocco sul player apre CarWeb" scrive la Main (`CarMediaService.applyPlayerCardTarget`), tranne quando suona la Wide. Niente componenti in più: un servizio di categoria media riceve il tocco ma aggiunge un'icona al menu, e un'app nascosta dal menu non lo riceve. Android Auto si collega al componente dichiarato anche come MediaBrowser, altrimenti la scheda resta vuota: `CarService` smista per azione e passa queste richieste a `CarMediaService`. Visto nel codice di Android Auto 18.1: una versione che non legge l'extra apre la Wide, come senza opzione.

\### Switching Between the Two Car Apps

- La Main ha il tasto «CarWebWide» in alto nella dashboard (solo in auto) e la home della Wide ha «↗ CarWeb» (`HomePage.OPEN_MAIN`, solo dalla home come gli altri `about:toggle_…`). Main → Wide: `startCarActivity` dell'SDK con il componente della Wide; Wide → Main: `MainHandOver.openMainSoon`. La Wide aperta dalla Main non passa la mano alla Main (`EXTRA_FROM_MAIN` e 5 s dal tasto). Servono entrambe le app nel menu di Android Auto: con la Wide nascosta il tasto della Main non la apre (prova dell'utente del 07/11/2026), e il codice non può togliere la Wide dal menu (è elencata per la sua categoria). Provate e tolte anche la Wide come app POI o meteo (template mappa con pannello): niente terza app.

\### Share to the Car

- Opzione "Condividi su CarWeb" (`AppSettings.shareToCarWeb`, acceso; `shareAlways`, spento): `ShareToCarActivity` è spenta nel manifest e `CarShareTarget` la accende con il telefono collegato all'auto (`CarConnection`, osservato dall'avvio dell'app, `setComponentEnabledSetting`) o sempre. Con "Sempre", lontano dall'auto, `VoiceCommandRouter.openOnPhone` e `MainActivity`: si apre una scheda della Main sul telefono. Android Auto annuncia il collegamento con un broadcast implicito (visto nel suo codice), che raggiunge solo le app già avviate: la voce compare quando CarWeb è avviata in auto (app aperta, o player collegato). Se è rimasta accesa dopo il viaggio (app chiusa durante il viaggio), al primo uso legge il collegamento, avvisa e si spegne. Il primo indirizzo web del testo condiviso (`SharedLink`: punteggiatura finale tolta, link di YouTube senza parametri di tracciamento e su m.youtube.com) va a `VoiceCommandRouter.openInCar` → `Command.OpenLink` → `Plan.Load` di tipo `LINK`, con una scelta diversa da quella dei comandi vocali: la Wide solo se è lei davanti (resumed e Main non resumed; conta anche quando sta nel riquadro mappa della home di Android Auto, l'app non lo distingue), altrimenti la Main, riportata davanti. Con la sola Wide aperta e dietro un'altra schermata la Wide apre la Main (`MainHandOver.openMainSoon`) e il link la aspetta (`pendingTarget`); senza app aperte aspetta 60 s quella che si apre. Un video di YouTube parte da solo (`autoplay`: la Wide toglie il gesto richiesto, la Main con `requestAutoplay` all'inizio della pagina). La Main sul telefono e quella in auto si registrano entrambe: vale quella in auto.
- Foto, video e file audio (`ACTION_SEND`, `image/*`, `video/*` e `audio/*`, uno alla volta, in una scheda: per quelli fissi c'è CarWeb Media): il permesso sul file finisce con l'attività che lo riceve, quindi `SharedMedia` lo chiede per l'app (`grantUriPermission` sul proprio pacchetto, restituito al file successivo). Li mostra `https://player.local/shared/<id>` (`assets/player/shared.html`, in memoria: dopo un riavvio dell'app la pagina lo dice), con i file serviti come quelli di CarWeb Media e il token. HEIC/HEIF convertite in JPEG perché la WebView non le legge. Non si accettano percorsi diretti né i file privati dell'app (l'attività è esportata).

\### AdBlock: Pop-ups and Pop-unders

- Lo script che intercetta `window.open` (`GoogleLoginManager.POPUP_INTERCEPTOR_JS`, in tutti i frame all'inizio della pagina) manda ogni finestra all'app: la Main la apriva in una scheda, la Wide al posto della pagina, quindi sui siti di streaming ogni tocco portava a una pubblicità. Ora lo script ricorda il link sotto l'ultimo tocco vero e chiede all'app (`AndroidBridge.allowsPopup`, `openInNewTab(url, link)`, `openPopup(url, link)`); `PopupGuard` apre solo verso lo stesso sito della pagina (sito = ultimi due pezzi dell'host, tre per co.uk e simili), il sito del link toccato o un accesso (parole all'inizio di un pezzo di host o percorso: oauth, login, signin, auth, sso, account; siti di pagamento). Ai pop-up bloccati lo script dà una finestra finta (con null molti script spostano la pagina stessa). Bloccati anche i link cliccati da uno script (`a.click()`, clic finti) verso altri siti. Nella pagina principale (`shouldOverrideUrlLoading`) mai le pagine delle liste dell'AdBlock, e per 2 s dopo una finestra aperta da uno script nessun altro sito toccato senza link ("tab-under"). Con l'AdBlock spento o lo scudo spento per il sito tutto come prima.
- Senza finestre multiple Blink apre `_blank` nel frame principale (`create_window.cc`): un link `_blank` dentro un riquadro sostituisce tutta la pagina. Lo script lo apre come le altre finestre (`openInNewTab`, solo nei riquadri, non i `download`). Link invisibili sopra il lettore (almeno metà del riquadro, fissi o assoluti, trasparenti, senza testo né immagini, verso un sito che `PopupGuard` non lascerebbe aprire): tolti, e il tocco passa all'elemento sotto. WebView non passa da `shouldOverrideUrlLoading` per gli indirizzi http(s) dei riquadri: le pagine bloccate rispondono 204 (`AdBlockHost.blockedResponse`, `Accept: text/html`) e resta quello che c'era.

\### AdBlock: Downloaded List

- `AdBlockLists`: si sceglie nelle Impostazioni (`AdBlockSettings.listKey`): HaGeZi Multi PRO di serie (`SOURCES`, da jsDelivr), PRO++, NORMAL, AdGuard DNS filter o l'indirizzo di una lista a piacere (`CUSTOM_KEY`, scritto solo dal telefono). Scaricata e mai distribuita con l'app (licenze GPL-3.0), all'avvio se più vecchia di tre giorni o se non è quella scelta, e dal tasto «Aggiorna»; quella di prima resta in uso finché la nuova non è arrivata. Si tengono le impronte FNV-1a a 64 bit dei domini, ordinate (2 MB per 250.000), in `noBackupFilesDir` (fuori dal backup), con indirizzo e nome della lista; un host è bloccato se lui o un dominio che lo contiene è nella lista e nessuno è nelle eccezioni (`@@`). Letti `||dominio^` (anche `$important`), `@@||dominio^`, `@@|host^|`, file hosts e un dominio per riga; `$badfilter` toglie la regola; saltati jolly, espressioni regolari, altre opzioni e le regole per nascondere elementi. Una lista nota con meno di 1000 domini (una scritta dall'utente: vuota) è un errore e non sostituisce quella salvata; al massimo 40 MB e 3 milioni di domini. Oltre alla lista, gli script dei circuiti che cambiano dominio a ogni ora con lo schema `/c7/93/5c/c7935c…(32 esadecimali).js` da un altro sito (`AdBlockHost.isRotatingAdScript`). YouTube resta fuori ([scriptManagedHosts]).

\### SponsorBlock on YouTube

- `assets/scripts/sponsorblock.js`, all'inizio delle pagine di YouTube (`YOUTUBE_ORIGINS`) nella Main e nella Wide; chiede al ponte le categorie (`sponsorBlockCategories`, "[]" se spento) e il messaggio (`sponsorBlockMessage`). Chiede `sponsor.ajay.app/api/skipSegments/<prime 4 cifre dello SHA-256 dell'id>` (CORS permesso, YouTube non limita `connect-src`, niente cookie) e tiene le parti `skip` di quel video lunghe almeno 1 s; salta su `timeupdate` (in cattura sul document) e ogni secondo, mai con `ad-showing`, ogni parte una volta sola, con un messaggio nella pagina (anche a schermo intero). Livelli (`AppSettings.sponsorBlockLevel`, `SponsorBlock.categories`): solo sponsor; più autopromozione e richieste di iscrizione (predefinito); più sigle, finali, anteprime e parti non musicali. Acceso di default. Dati CC BY-NC-SA 4.0 (citati nel README). Test: `node --test browser/src/test/js/`.

\### Gemini and Assistant in the Car

\- La sessione media accetta la ricerca vocale standard (`ACTION_PLAY_FROM_SEARCH`, `onPlayFromSearch` → `VoiceCommandRouter.fromAssistant`), quella del vecchio Assistente. Gemini non la usa per CarWeb: nelle prove del 07/11/2026 non è mai arrivato niente, né ad Android Auto né alla sessione, anche con un'app media "CarWeb" nel menu (opzione provata e tolta). Diagnosi nelle build di debug: tag `CarWebVoiceDebug` (chiamante, testo ed extra di `onPlayFromSearch`, comando, schermata scelta, piano eseguito). Sul telefono Gemini usa solo app partner di Google; AppFunctions (Android 16) è in anteprima privata.

\### Media & Audio Handling

\- \*\*DRM Support\*\*: Widevine L3 implementation.

\- \*\*Audio Focus\*\*: Automatically pauses/ducks playback during reverse gear / rear parking camera activation.

\- \*\*Tasti al volante\*\*: Android Auto li inoltra alla sessione, ma il comportamento predefinito di Android scarta ⏭ e ⏮ se lo stato non li dichiara. Su un video senza brani (stato con `ACTION_SEEK_TO` e senza skip) li gestisce `CarMediaService.onMediaButtonEvent`: ±10 s subito, come i pulsanti di Android Auto, e i tocchi ravvicinati si sommano. Opzione nelle Impostazioni, solo YouTube (`AppSettings.youtubeVideoSkip`, spenta): lo stato dichiara lo skip (`MediaSessionManager.singleVideoAsTracks`), ⏭ apre il primo video suggerito (`ytm-video-with-context-renderer`) e ⏮ torna all'inizio, o alla pagina di prima se è già all'inizio. Un «successivo» detto a voce («avanti», «manda avanti») apre comunque il video suggerito: senza skip dichiarato `onSkipToNext` arriva solo da una richiesta esplicita (`sendPlayerCommand`), mai dai tasti.

\- \*\*Media Player\*\*: Integrated player with options to disable completely or run in the background. Local audio tracks can look up plain or synchronized lyrics on LRCLIB using their tags; playback-time highlighting is available for synchronized lyrics.

\## 4. Rules & Guidelines for AI Agents

When modifying code, refactoring, or generating files for AABrowser, strictly adhere to the following rules:

\### Code Formatting & Maintenance

1\. \*\*Optimize Imports\*\*: Always remove unused imports and keep import blocks clean (\`Ctrl + Alt + O\` / IntelliJ standard).

2\. \*\*Architecture Separation\*\*: Keep Classic Mode (standard WebView) logic cleanly separated from Widescreen Mode (Car App Library templates) to avoid regressions.

3\. \*\*Log Security\*\*: Never log raw URLs, tokens, or personal context using standard \`Log.d\` / \`Log.e\`. Always wrap logs through the \`AppLog\` sanitizer class.

4\. \*\*Dependency Management (TOML)\*\*: Always define dependencies and library versions in \`gradle/libs.versions.toml\` (Version Catalog). Never hardcode dependency strings directly in \`build.gradle\` files.
